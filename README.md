# Generic Divige — Combo Lab

意図してパネルを揃える操作感を試す、ブラウザ用の小さなPoCです。独自のCSS・SVG・図形を使用しています。原作の画像・UI・音声は含みません。

## 起動

Node.js 22.12以降（検証環境: 24.12.0）。

```sh
npm ci
npm run dev -- --port 4187 --strictPort
```

ブラウザで http://127.0.0.1:4187/ を開きます。マウスまたはタッチで操作できます。ローカル専用で、アカウント・保存・外部通信・バックエンドはありません。

## 遊び方

- 手札は常に5枚、場は5枠、各枠は5枚まで。同色の攻撃パネル2枚で1攻撃です。
- 最初の有効な配置までは時間無制限。手札内でドラッグして並べ替えられます。
- 掴んだ時点では必ず1枚です。隣接する同色も、そのまま場へ運べば1枚だけ置けます。
- 束にするには、保持したまま隣の同色カードの中央をなぞります。触れた隣1枚ずつ追加され、残りの同色列は自動選択されません。束の両端から追加でき、異色や非隣接カードは取り込めません。中央60%を巻き込み範囲とし、端をかすめる操作では追加しません。束は離すまで保持されます。
- 場に置くと即座に補充され、5カウントの進行が始まります。まとめ置きで容量を超える場合は全枚数を戻します。
- Hは枚数に応じてHeal I〜Vへ強化。同じ枠の回復は1コンボです。攻撃と回復は混在できます。
- カウント間隔は400〜2000 ms/count。初期1000は試遊用の値です。途中変更は、それまでの進行を保って以後の速さだけを変えます。
- 演出の速さは0.25〜2倍。ドラッグ追従・補充・ゲームの時間や結果には影響しません。
- 「もう一度」またはシナリオ切替で手札と補充順を再現。スライダーの値は維持します。

## 3つの固定シナリオ

| シナリオ     | 目標               | 操作例                                                              |
| ------------ | ------------------ | ------------------------------------------------------------------- |
| A 基本コンボ | A・B・C攻撃        | 隣をなぞってAAを枠1、Bを2枚枠2、Cを2枚枠3へ。必要なら1枚置きや並べ替えを使う |
| B 捨てる判断 | A・B攻撃           | 初期手札4枚を枠5へ逃がして補充し、AとBを各2枚揃える                 |
| C 攻撃と回復 | A攻撃＋Heal IV以上 | AAを枠1、HHを枠2へ。補充Hを同じ回復枠へ追加してVまで強化            |

各シナリオは25枚の固定補充キューを持ちます。接頭部分の後に `A B C D E H A A B B C C D D E E H H H A B C D E H` を続け、全体25枚で切ります。乱数や枯渇時のランダム補充はありません。成功手順と最大容量は単体テストで検証します。

## 検証

```sh
npm run lint
npm run typecheck
npm run test:unit
npx playwright install chromium
npm run test:e2e
npm run build
```

Playwrightは4187番のローカル開発サーバーを使います。既にこのアプリが起動していれば再利用します。別アプリがそのポートを使用している場合は、そのアプリを停止せず設定を変更してください。デスクトップと狭いタッチ対応画面で検証します。操作後スクリーンショットは `docs/scenario-*.jpg`、失敗時トレースは `test-results/` に出力します。

## 設計と制限

`src/domain` はパネル・レシピ・ラウンド・カウントの純粋モデル、`src/ui` は入力・描画・演出・メモリ内計測、`src/main.ts` は接続と画面ライフサイクルです。外部テレメトリはありません。計測はDOM更新までのブラウザ側近似値で、ハードウェア入力から発光までの遅延ではありません。

仕様は利用者が提供したゲーム要件と実装計画に基づきます。非公開の会話や他資料は収録しません。今回の判断は、5枚容量、原子的まとめ置き、場への保持、訓練ターゲットへの結果表示、固定キューという可逆なPoC範囲です。

戦闘バランス・ランダムモード・音・セーブ・コレクションは対象外。機械的に遊べることと、気持ちよさ・面白さは別です。後者は実際に触って評価してください。
